    Access contracts: Citadel vs. Azure AI Gateway

    Same intent: give a support workload only its approved model and tools.

    Two animated walkthroughs
    Citadel / API Management

    One contract bundles access and policy

    The accelerator creates an APIM product, API associations, and subscription for the use case. In the illustrated JWT-enabled contract, the caller uses both an APIM subscription key and an Entra token.

    Azure AI Gateway / Entra ID

    Use scoped role assignments instead of handing out a key

    Give the workload identity the Models User role on one alias and the Tools User role on one MCP server. The runtime presents a short-lived bearer token without an APIM product or subscription key.

    DecisionCitadel access contractAzure AI Gateway equivalent or gap
    Who may call?The generated subscription selects the product; the JWT-enabled sample also validates the caller token and required role.Assign AI Gateway Models User on the alias and AI Gateway Tools User on the MCP server to a workload principal or appropriate group. AI Gateway User can cover both types; avoid broad inherited roles unless intended.
    What may they call?API associations and product policy narrow the permitted models or assets.Use alias and MCP server scopes. The Tools User role is not a per-tool entitlement: use server tool allow/block lists, or publish distinct narrowly configured servers when groups need different tool sets.
    How much?The sample meters consumption by APIM subscription; the mixed contract can use distinct counters per asset type.Configure a gateway or asset policy and choose the counter. Caller identity can distinguish Entra callers by tid and oid. Claim-based cost overrides change each matching caller's allowance; they do not create a shared team budget.
    Which credential reaches the backend?The gateway has its own outbound configuration; the subscription and caller JWT do not grant backend access.Configure outbound managed identity or a supported backend credential separately. For supported MCP backends, explicitly configure delegated on-behalf-of (OBO) when the backend must authorize the actual user.
    What does not map?The mixed sample bundles model, MCP and A2A access with custom product-policy logic.Do not assume a one-to-one product bundle, arbitrary APIM XML parity, or A2A asset-level RBAC parity from the documented model and MCP roles. Verify each needed control independently.

    Suggested rollout: Keep a versioned per-use-case record of principal, environment, exact alias and MCP server, policy settings, backend auth, and allow/deny tests. That can remain your team's “access contract,” even though the runtime uses native RBAC and policies. Verify an allowed alias and MCP server, a valid identity denied access to another alias, and a disallowed tool on the allowed server. Gateway API keys are broader than asset-scoped Entra access, so don't treat one as a per-contract replacement.

    What's new in Azure AI Gateway

    Selected capabilities from the official gateway documentation and release notes; not an exhaustive availability matrix.

    Preview · MCP

    Agent Hooks

    Send an inline allow/deny decision to your own governance service before or after a tool call. A pre-call deny stops execution; a post-call deny withholds the result but can't undo side effects. Default failClosed blocks remote evaluation failures. failOpen permits continuation on those failures, not on explicit denies or failed local checks. Hooks are synchronous verdicts, not transforms or fire-and-forget callbacks.

    Policy guide · Policy reference

    Identity · MCP

    On-behalf-of backend authentication

    A configured MCP endpoint can exchange a delegated gateway token for a delegated backend token so the backend authorizes the signed-in user. This requires backend permissions and consent plus trusted managed identity for token exchange. An API key or app-only token cannot supply a user identity.

    Gateway release notes
    Routing · Models

    Alias failover rules

    Priority and weight choose among configured deployments. Separately, configured failure rules can retry the same backend, switch to another eligible deployment, or temporarily exclude a failing backend within a per-request retry limit. A weighted split alone does not configure failover.

    Gateway release notes on failover · Routing lab
    Governance · MCP

    Microsoft Agent 365 and threat protection

    Agent 365 inventories MCP servers and can block servers or tools; individual tool controls require a static allowed-tool list. Separately, tool threat protection applies Defender and Purview checks when configured with eligible licensing and delegated Entra user authentication. It is not the custom Agent Hooks policy.

    Agent 365 governance lab · Threat protection lab
    Spend · Monitoring

    Identity-based budgets and attribution

    Cost policies can override the default amount for a matching identity or validated token claims. The first matching override wins. Configured OpenTelemetry exports can carry selected claims; the gateway also accounts for streamed tokens without requiring the client to request usage.

    Budget lab · OpenTelemetry lab · Streaming lab
    Tooling · MCP

    Federated sources and protocol versions

    Compose a single endpoint from sources such as remote MCP servers, OpenAPI services, managed connectors, and Foundry Toolbox. Choose supported protocol versions on the server, including MCP 2026-07-28 where supported.

    Deployment blueprint

    What you configure before any of these requests can run.

    Guidance, not a deployment tool
    01 / Resource

    Provision the gateway

    Create a Microsoft.ApiManagement/aigateways resource. Choose the supported ingress and backend networking for your deployment. For private backends, plan network integration and name resolution explicitly.

    Provisioning lab · Private networking lab
    02 / Supply

    Publish models and tools

    Configure providers and backend models, then publish an alias clients can use. Register MCP sources under a federated endpoint and decide which namespaced tools to expose.

    Multi-provider aliases lab · MCP federation lab
    03 / Governance

    Scope identity and guardrails

    Give callers appropriate runtime keys or Entra role assignments. Configure backend credentials or managed identity separately. Apply and verify limits, budgets and content-safety policies where supported.

    Entra and RBAC lab · Backend identity lab · Gateway baselines lab
    04 / Operations

    Verify allowed and denied outcomes

    Run a known-good request, check policy failures and the chosen backend, and verify Monitoring. If exporting identity claims for attribution, choose only what you need and check what the callers' tokens actually carry.
